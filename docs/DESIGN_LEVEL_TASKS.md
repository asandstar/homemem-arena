## 一、设计理念

### 1.1 记忆类型梯度

本方案以认知神经科学中的记忆系统分类为骨架，按"由低到高、由单一到综合"的顺序排布五关，让玩家在不知不觉中走完一条完整的记忆训练曲线：

```
L1 程序记忆（Procedural）   →  L2 空间记忆（Spatial）  →  L3 工作记忆（Working）
        ↓                            ↓                           ↓
   肌肉记忆/动作序列           物体位置/房间布局           规则保持+规则切换
        ↓                            ↓                           ↓
L4 情境记忆（Episodic）     →  L5 综合记忆（All Types）
        ↓                            ↓
   事件序列/时序还原          多记忆协同+混沌干扰
```

- **L1 程序记忆**：玩家第一次进入游戏，需要把"移动→拾取→放置→开关容器"这套动作序列内化为肌肉记忆。不要求记忆物体本身，只要求"会做"。
- **L2 空间记忆**：玩家已经会操作，开始需要记住"物品在哪个房间的哪个位置"。猫把物品藏到不同房间，玩家必须在脑中构建房屋地图。
- **L3 工作记忆**：在前两关基础上，引入"边做边记规则"的工作记忆负荷。规则中途切换，迫使玩家抑制旧规则、加载新规则。
- **L4 情境记忆**：要求玩家记住"发生了什么、按什么顺序发生"，即带时间戳的事件序列。这是最高阶的单项记忆。
- **L5 综合记忆**：把前四关的记忆类型混合，并用真正生效的混沌值系统施加干扰，考验玩家在压力下的记忆调度能力。

### 1.2 难度曲线设计

| 维度 | L1 | L2 | L3 | L4 | L5 |
|------|----|----|----|----|----|
| 房间数 | 1 | 4 | 1 | 4 | 5 |
| 物品数 | 9 | 4 | 6 | 5（路径点） | 12 |
| 时限 | 无 | 90s | 120s | 180s | 240s |
| 干扰事件 | 0 | 2 | 1（规则切换） | 3 | 5+（混沌驱动） |
| 记忆槽压力 | 低 | 中 | 高 | 中 | 极高 |
| 容错率 | 高（无限重试） | 中 | 中 | 低 | 低 |

难度递增的三个杠杆：
1. **空间复杂度**：单房间 → 多房间 → 全屋
2. **认知负荷**：单一规则 → 双规则切换 → 序列还原 → 多任务并行
3. **外部干扰**：无干扰 → 猫偶发移动 → 规则反转 → 路径扰动 → 混沌系统全面生效

### 1.3 每关的教学目标

| 关卡 | 教学目标（玩家通关后应掌握） |
|------|------------------------------|
| L1 | 基本交互：WASD 移动、鼠标转视角、E 保存记忆、F 拾取/放置、容器可开关 |
| L2 | 房间导航：看小地图、跨房间寻物、应对物品位移（记忆失效→重新寻找） |
| L3 | 规则切换：在脑中保持当前生效规则、抑制过期规则、识别"规则变了"的信号 |
| L4 | 序列还原：观察事件顺序、按序复现、抵抗中间插入的干扰事件 |
| L5 | 压力管理：在混沌干扰下优先级排序、动态调整策略、容忍不完美 |

### 1.4 叙事总纲

五关串联成一个完整的"家庭一日"故事，以"钥匙猫"（一只会偷东西的橘猫，脖子上挂着一把永远丢不了的旧钥匙）为贯穿 L2-L5 的反派/伙伴：

- **L1 清晨**：管家机器人 MEM-07 记忆模块故障，主人让它从餐桌整理开始重启。这是平静的教程。
- **L2 上午**：主人要出门，发现钥匙、手机、雨伞、钱包都不见了——钥匙猫清晨恶作剧，把东西藏到全屋各处。
- **L3 下午**：主人要洗衣服，钥匙猫把洗衣篮的标签撕了，还把规则贴纸换了。玩家要在规则切换中完成分拣。
- **L4 深夜**：主人睡着，钥匙猫在屋里夜游。玩家要跟踪它的路径，按顺序找到它经过的所有停留点（情境记忆）。
- **L5 凌晨**：混沌值累积到临界，屋里开始"闹鬼"——风吹门、电器断电、物品自己移位。玩家要在混沌中完成多重任务，平息这场记忆风暴。

## 三、各关卡详细设计

### L1 · 餐桌整理

#### 3.1.1 故事背景

清晨 7:00，阳光透过餐厨的窗帘洒进来。管家机器人 MEM-07 的记忆模块刚做完夜间重启，所有程序性记忆（"怎么做事"）都需要重新校准。主人留下一张便签：「小橡，餐桌昨晚聚餐后没收拾，你先把餐具归位，慢慢来，别急。」这是 MEM-07 重启后的第一项任务，也是它"重新学会动手"的过程。

#### 3.1.2 关卡目标

- **教学目标**：让玩家内化"移动→拾取→放置→开关容器"的动作序列（程序记忆）
- **记忆目标**：不强调记忆负荷，重在动作流畅度
- **通关目标**：将 9 件餐具全部归位到正确容器

#### 3.1.3 场景设置

- **房间**：`dining`（餐厨一体）
- **容器列表**：

| 容器 ID | 名称 | 位置（局部坐标） | 接受类别 | 初始状态 | GLB 模型 |
|---------|------|------------------|----------|----------|----------|
| `cnt-dining-table` | 餐桌 | (0, 0, 0) | -（物品源） | 开 | furniture/table |
| `cnt-sink` | 厨房水槽 | (1.8, 0, 1.8) | cup, spoon | 开 | furniture/kitchenSink |
| `cnt-cabinet` | 橱柜 | (-1.8, 0, 1.8) | plate, fork | 开 | furniture/kitchenCabinetDrawer |
| `cnt-trashcan` | 垃圾桶 | (1.5, 0, -1.5) | trash (果皮残渣) | 关（需玩家打开） | furniture/trashcan |

- **物品列表**（全部有 GLB 模型）：

| 物品 ID | 名称 | 数量 | GLB 模型 | 初始位置 | 目标容器 |
|---------|------|------|----------|----------|----------|
| `obj-mug-1` / `obj-mug-2` | 马克杯 | ×2 | food/mug | 餐桌左侧 | 水槽 |
| `obj-spoon-1` / `obj-spoon-2` / `obj-spoon-3` | 勺子 | ×3 | food/utensil-spoon | 餐桌前侧 | 水槽 |
| `obj-plate-1` / `obj-plate-2` | 盘子 | ×2 | food/plate | 餐桌中央 | 橱柜 |
| `obj-fork-1` / `obj-fork-2` | 叉子 | ×2 | food/utensil-fork | 餐桌右侧 | 橱柜 |

#### 3.1.4 游戏流程

1. **开场对话**（briefing 阶段）：MEM-07 自我介绍 + 主人便签 + 操作说明
2. **示范高亮**（step=1~3）：依次高亮 3 个目标容器（水槽→橱柜→垃圾桶），用 `activeDemoHighlights` 推入脉冲，每个持续 1.8s
3. **玩家操作**（playing 阶段）：
   - 拾取餐桌上的餐具（按 F）
   - 走到对应容器前放置（按 F）
   - 垃圾桶初始关闭，需先按 F 打开才能放入残渣类物品
4. **完成判定**：9 件物品全部 `placedIn` 正确容器
5. **结算**：播放完成动画 + `completionText`

#### 3.1.5 完成条件

- 所有 9 件物品 `status === 'placed'` 且 `placedIn` ∈ 正确容器集合
- 具体判定（参考 `taskSlice.checkLevelCompletion`）：
  - `obj-mug-1/2` → `cnt-sink`
  - `obj-spoon-1/2/3` → `cnt-sink`
  - `obj-plate-1/2` → `cnt-cabinet`
  - `obj-fork-1/2` → `cnt-cabinet`

#### 3.1.6 失败条件

- **无时限**：L1 不设 `timeLimit`，鼓励玩家慢慢探索
- **无失败惩罚**：放错位置不会扣分扣血，仅提示"这个容器好像不对哦"
- **唯一"失败"**：玩家主动放弃（按 ESC 返回主菜单），但进度会保存

#### 3.1.7 对话脚本

**开场（briefing）**：
```
MEM-07：「系统重启完成。我是 MEM-07，您的家庭记忆管家。检测到……我的程序记忆模块还在校准。」
MEM-07：「没关系，从最简单的餐桌整理开始就好。主人留了便签。」
主人便签：「小橡，餐桌昨晚没收拾，你先把餐具归位，慢慢来。杯勺碗 → 水槽；盘 → 橱柜。洗碗机也能放杯碗，但得先打开。」
MEM-07：「WASD 移动，鼠标转视角，靠近物品按 F 拾取，走到发光的目标区再按 F 放置。准备好了吗？」
```

**进行中（step=2、step=5、step=10）**：
```
[step=2]  MEM-07：「看，水槽在亮——杯子和勺子放这里。」（高亮 cnt-sink）
[step=5]  MEM-07：「对了，洗碗机现在是关着的。靠近它按 F 就能打开。」（高亮 cnt-dishwasher）
[step=10] MEM-07：「已经放对一半了！程序记忆正在重新校准，感觉越来越顺手了对吧？」
```

**结尾（completion）**：
```
MEM-07：「9 件餐具全部归位。程序记忆校准完成度：98.7%。剩下的 1.3% 是……我好像忘了自己有没有关洗碗机。」
MEM-07：「玩笑啦。下一关会更难哦——钥匙猫要出场了。」
```

#### 3.1.8 混沌效果

- **无**。L1 混沌值始终为 0，是纯净的教程环境。

### L2 · 钥匙猫的清晨恶作剧

#### 3.2.1 故事背景

上午 8:30，主人准备出门，发现客厅茶几上的四件日常物品全不见了——书、马克杯、玩具熊、收音机。屋角传来一声"喵"——钥匙猫正舔着爪子。原来清晨 6 点，钥匙猫趁所有人熟睡，把四件东西藏到了不同房间。玩家要在 90 秒内找到全部物品并放回客厅茶几，否则主人出门前来不及找到。

> **资产约束说明**：原设计中的钥匙/手机/钱包/雨伞无对应 GLB 模型，已替换为已有资产的书籍/马克杯/玩具熊/收音机。钥匙猫作为叙事角色（对话+猫脚印特效），不需要 3D 猫模型。

#### 3.2.2 关卡目标

- **记忆目标**：构建"哪个物品藏在哪个房间"的空间地图
- **教学目标**：学会跨房间导航、应对物品位移（记忆失效后重新寻找）
- **通关目标**：90 秒内找到 4 件物品并全部放回客厅茶几

#### 3.2.3 场景设置

- **房间**：`living`、`bedroom`、`dining`、`entrance`（4 房间）
- **容器列表**（全部有 GLB 模型）：

| 容器 ID | 名称 | 房间 | GLB 模型 | 用途 |
|---------|------|------|----------|------|
| `cnt-coffee-table` | 客厅茶几 | living | furniture/tableCoffee | 唯一目标区（4 件物品都放这里） |
| `cnt-living-sofa` | 客厅沙发 | living | furniture/loungeSofa | 钥匙猫藏书籍处（隐藏，需翻找） |
| `cnt-bedroom-pillow` | 卧室枕头 | bedroom | furniture/pillow | 钥匙猫藏马克杯处（隐藏） |
| `cnt-dining-fridge-top` | 厨房冰箱顶 | dining | furniture/kitchenFridge | 钥匙猫藏玩具熊处（可见但高处） |
| `cnt-entrance-cabinet` | 玄关柜 | entrance | furniture/sideTableDrawers | 钥匙猫藏收音机处（隐藏） |

- **物品列表**（全部有 GLB 模型）：

| 物品 ID | 名称 | GLB 模型 | 初始藏匿处 | 目标 |
|---------|------|----------|-----------|------|
| `obj-books` | 书 | furniture/books | 客厅沙发缝（隐藏，需按 F 翻找） | 客厅茶几 |
| `obj-mug` | 马克杯 | food/mug | 卧室枕头下（隐藏） | 客厅茶几 |
| `obj-bear` | 玩具熊 | furniture/bear | 厨房冰箱顶（可见但高处） | 客厅茶几 |
| `obj-radio` | 收音机 | furniture/radio | 玄关柜内（隐藏） | 客厅茶几 |

#### 3.2.4 游戏流程

1. **开场对话**：主人催促 + 钥匙猫挑衅
2. **寻物阶段**（0~60s）：玩家跨房间搜寻，隐藏物品需靠近容器按 F "翻找"才显形
3. **钥匙猫二次恶作剧**（step=8）：若玩家已找到 2 件，钥匙猫会把已找到的某件物品再次藏起（`move-entity` 到另一房间），触发记忆失效
4. **归位阶段**：把找到的物品带回玄关托盘
5. **完成判定**：4 件物品全部 `placedIn === 'cnt-entrance-tray'`
6. **结算**：主人道谢 + 钥匙猫傲娇

#### 3.2.5 完成条件

- 4 件物品全部 `status === 'placed'` 且 `placedIn === 'cnt-coffee-table'`
- 在 `task.timeLimit`（90 秒）内完成

#### 3.2.6 失败条件

- **超时**：90 秒到，未集齐 4 件 → `setLevelFailed('任务超时')`
- **宽松处理**：
  - 不因"放错容器"失败，只是放回手持
  - 钥匙猫二次恶作剧最多触发 1 次，不无限循环
  - 失败后提示"再来一次，这次记得先去 X 房间"（基于已找到的物品给提示），鼓励重试

#### 3.2.7 对话脚本

**开场（briefing）**：
```
主人：「完了完了！我的书、杯子、小熊、收音机全不见了！我要出门了！」
钥匙猫：「喵~」（舔爪子，眼神无辜）
MEM-07：「检测到钥匙猫清晨活动轨迹。四件物品被分散藏匿于客厅、卧室、厨房、玄关。」
MEM-07：「90 秒内找回并放到客厅茶几。隐藏物品需要靠近容器按 F 翻找。小心——钥匙猫可能会再捣乱。」
```

**进行中**：
```
[找到第1件] MEM-07：「找到一件了！记得它的位置，钥匙猫可能会再动它。」
[step=8 钥匙猫二次恶作剧]
  钥匙猫：「喵呜~」（叼着你刚找到的玩具熊跑到卧室）
  MEM-07：「警告！钥匙猫把玩具熊叼走了！位置记忆已失效，请重新寻找。」
  系统：触发 `markMemoryOutdated: 'obj-bear'`
[剩余30s] MEM-07：「还剩 30 秒！主人已经在门口跺脚了。」
```

**结尾（completion）**：
```
主人：「太及时了！东西都找到了！小橡你真靠谱。」
钥匙猫：「喵~」（跳上书架，尾巴甩了甩，似乎在策划下一次）
MEM-07：「空间记忆模块校准完成。但钥匙猫……它的活动模式我还没完全掌握。」
```

#### 3.2.8 混沌效果

- **轻微**：钥匙猫二次恶作剧时 `incrementChaos(8)`（`eventChaos`），但 L2 整体混沌值不会超过 30，不触发任何阈值效果。
- 混沌值在此关仅作为"恶作剧计数器"展示，让玩家熟悉这个 HUD 元素。

### L3 · 衣物分类

#### 3.3.1 故事背景

下午 15:00，主人抱着一堆衣服走进洗衣房：「小橡，这批衣服分三类——浅色、深色、毛巾。浅色放白篮，深色放蓝篮，毛巾放橙篮。我去做饭，你搞定！」钥匙猫跟了进来，一屁股坐在规则贴纸上，尾巴有节奏地拍打。三十秒后，主人探头：「哎呀我说错了！这批衣服不按颜色分，按材质分——棉的放白篮，化纤的放蓝篮，毛巾还是橙篮。刚才的颜色规则作废！」玩家要在规则切换的情况下，重新调整已分好的衣物，并记住"现在生效的是哪条规则"。

#### 3.3.2 关卡目标

- **记忆目标**：在工作记忆中保持"当前规则"，并在切换时抑制旧规则
- **教学目标**：识别规则切换信号、动态更新脑中规则、纠正已做出的动作
- **通关目标**：6 件衣物全部按"最终规则"（材质）归位

#### 3.3.3 场景设置

- **房间**：`laundry`
- **容器列表**（沿用现有 `laundry-sort` 配置）：

| 容器 ID | 名称 | 位置 | 颜色规则下接受 | 材质规则下接受 |
|---------|------|------|---------------|---------------|

#### 3.3.4 游戏流程

1. **开场对话**：主人宣布颜色规则（前 30 秒生效）
2. **规则编码阶段**（STAGE_RULES，0~30s）：玩家观察三个篮子 + 6 件衣物，按 E 保存"颜色规则"记忆，开始按颜色分拣
3. **规则切换事件**（step=对应 30s 时）：主人探头改口，触发 `se-rule-switch` 事件
   - 所有已放置物品的 `acceptedCategories` 动态切换为材质规则
   - 触发 `swapContainers('cnt-white-basket', 'cnt-dark-basket')` 干扰（钥匙猫拍桌子震歪篮子）
4. **重新分拣阶段**（STAGE_RESORT）：玩家需识别哪些物品目标变了，取出重放
5. **完成判定**：6 件物品全部按材质规则归位
6. **结算**：主人惊讶 + 钥匙猫打哈欠

#### 3.3.5 完成条件

- 6 件物品 `placedIn` 匹配**材质规则**（不是颜色规则）：
  - `obj-item-1` → `cnt-white-basket`（cotton）
  - `obj-item-2` → `cnt-dark-basket`（synthetic）
  - `obj-item-3` → `cnt-white-basket`（cotton）
  - `obj-item-4` → `cnt-dark-basket`（synthetic）
  - `obj-item-5` → `cnt-towel-basket`
  - `obj-item-6` → `cnt-towel-basket`
- 在 `task.timeLimit`（120 秒）内完成

#### 3.3.6 失败条件

- **超时**：120 秒到，未全部按材质规则归位
- **宽松处理**：
  - 规则切换前放错的物品不扣分（毕竟规则还没变）
  - 切换后放错仅提示"现在按材质分啦"，不锁定篮子
  - 失败后提示"记得：规则切换后要重新检查所有已放物品"

### L4 · 深夜巡逻

#### 3.4.1 故事背景

深夜 02:00，主人熟睡，MEM-07 启动夜间巡逻模式。监控显示钥匙猫从客厅出发，依次经过卧室、厨房、玄关，在每个房间都停留了一会儿，最后回到客厅窗台。玩家要在黑暗中（视野受限）按**钥匙猫经过的顺序**找到它每个停留点的"痕迹"（一撮猫毛、一个爪印、一个被碰歪的小物件），并按序确认。中途会有夜间扰动事件（电器异响、窗户晃动）插入，干扰玩家的序列记忆。

#### 3.4.2 关卡目标

- **记忆目标**：记住钥匙猫路径的**顺序**（情境记忆：什么先发生、什么后发生）
- **教学目标**：观察事件序列、按序复现、抵抗时序干扰
- **通关目标**：按正确顺序找到 5 个停留点 + 应对 1 次路径扰动

#### 3.4.3 场景设置

- **房间**：`living` → `bedroom` → `dining` → `entrance` → `living`（回到起点）
- **路径点（停留点）容器**：

| 顺序 | 容器 ID | 房间 | 痕迹描述 |
|------|---------|------|----------|
| ① | `cnt-trace-living-sofa` | living | 沙发上一撮橘猫毛 |
| ② | `cnt-trace-bedroom-pillow` | bedroom | 枕头上一个爪印 |
| ③ | `cnt-trace-dining-counter` | dining | 厨房台面一个被碰歪的杯子 |
| ④ | `cnt-trace-entrance-rug` | entrance | 玄关地毯一串泥爪印 |
| ⑤ | `cnt-trace-living-bookshelf` | living | 书架上层钥匙猫蜷缩的痕迹（用 bookcaseOpenLow 模型） |

- **路径记忆目标**（goal）：使用 `requiredSequence` 强制玩家按 ①→②→③→④→⑤ 顺序"按 F 确认"
- **扰动事件**：第 ③ 步确认后，钥匙猫会从书架跳下，把第 ④ 点的痕迹蹭掉，玩家需重新寻找新位置（`move-entity`）

#### 3.4.4 游戏流程

1. **开场对话**：MEM-07 报告夜间异常 + 展示钥匙猫路径预告（用 `activeDemoHighlights` 依次高亮 5 个点，每个 1.2s，玩家需记住顺序）
2. **编码阶段**（STAGE_ENCODE）：玩家观看 5 个点的高亮示范，按 E 保存"路径序列"记忆
3. **复现阶段**（STAGE_REPRODUCE）：玩家在黑暗中按顺序找到每个点，按 F 确认
   - 错误顺序：拒绝确认，提示"这不是钥匙猫下一个停留点"
   - 正确顺序：痕迹消失，进度 +1
4. **扰动事件**（确认第 ③ 点后）：钥匙猫蹭掉第 ④ 点痕迹，`move-entity` 到新位置，`markMemoryOutdated`
5. **完成判定**：5 个点按序确认 + 第 ④ 点扰动后重新确认
6. **结算**：钥匙猫回到窗台 + MEM-07 总结

#### 3.4.5 完成条件

- `proceduralProgress['g-cat-path-sequence'].completed === true`
- 即 5 个点按 ①→②→③→④→⑤ 顺序全部确认
- 扰动后第 ④ 点的新位置也已被确认
- 在 `task.timeLimit`（180 秒）内完成

#### 3.4.6 失败条件

- **超时**：180 秒到，序列未完成
- **宽松处理**：
  - 错误顺序不扣分，仅拒绝确认（参考 L2 睡前仪式的设计）
  - 玩家可随时按 Tab 查看路径预告回放（但会消耗 5 秒，鼓励记忆而非依赖回放）
  - 失败后提示"钥匙猫的路径是：客厅→卧室→厨房→玄关→客厅窗台"

### L5 · 混沌来袭

#### 3.5.1 故事背景

凌晨 04:00，MEM-07 的混沌值监测器突然报警——过去一天的累积混沌值突破临界点，屋里开始"闹鬼"了。风吹得门乱晃，电器随机断电，物品自己移位。主人还在睡，但屋里已经乱成一锅粥。钥匙猫坐在客厅中央，眼神诡异，似乎它就是这一切的源头——它脖子上那把旧钥匙，其实是一个"混沌锚点"。玩家要在混沌全面生效的情况下，完成四项迷你任务（呼应 L1-L4 的记忆类型），平息这场记忆风暴。

#### 3.5.2 关卡目标

- **记忆目标**：综合调用程序、空间、工作、情境四种记忆
- **教学目标**：在压力下优先级排序、动态调整策略、容忍不完美
- **通关目标**：240 秒内完成 4 项迷你任务 + 混沌值未达 100

#### 3.5.3 场景设置

- **房间**：全屋 5 房间（`living`、`bedroom`、`dining`、`entrance`、`laundry`）
- **4 项迷你任务**（每项呼应一关）：

| 迷你任务 | 呼应关卡 | 记忆类型 | 内容 | 房间 |
|---------|---------|---------|------|------|
| MT1 · 餐具归位 | L1 | 程序 | 3 件餐具放回正确容器 | dining |

## 四、混沌值系统设计

### 4.1 现状与改进方向

**现状**（基于 `src/data/levelBalance.ts` + `src/game/chaos.ts`）：
- 混沌值 0~100，`chaosGrowthPerSecond = 0.3` 自然增长
- 错误放置 +12，事件触发 +8，正确放置 -15
- 达到 100 触发 `setLevelFailed('混乱值过载')`
- `getMemoryDecayMultiplier`：30 以下 ×1，30~60 ×1.5，60~80 ×2，80+ ×3
- `getRandomEventProbability`：50 以下 0%，50~70 2%，70~85 5%，85+ 10%
- **问题**：`getRandomEventProbability` 已定义但**未在游戏循环中实际调用**触发事件，混沌值目前只影响记忆衰减和 HUD 显示，玩家感受不到"混乱"。

**改进方向**（本设计 L5 落地）：
- 在 L5 的 `tickElapsed` 中，根据 `getChaosLevel(chaosValue)` 调用对应的混沌效果触发器
- 每个阈值区间有明确的玩法影响（视觉/交互/物品位置）
- 混沌值不再只是"扣分计数器"，而是 L5 的核心机制

### 4.2 阈值效果表

| 混沌值区间 | 等级 | 视觉效果 | 玩法影响 | 触发频率 |
|-----------|------|---------|---------|---------|
| 0~30 | low（正常） | HUD 绿色 | 无 | - |
| 31~60 | medium（微乱） | HUD 黄色 + 偶尔画面抖动 | 风吹门声 + 门偶尔自动关上（需重新按 F 开门） | 每 20s 概率 30% |
| 61~80 | high（混乱） | HUD 红色 + 持续轻微抖动 | 电器随机断电 10s（容器临时 `disabled`，不可交互） | 每 15s 概率 50% |
| 81~100 | critical（失控） | HUD 深红 + 强烈抖动 + glitch | 物品自动移位（随机 `move-entity` 一个非已完成物品） | 每 15s 必触发 1 次 |

### 4.3 实现要点

#### 4.3.1 风吹门（31~60）

```typescript
// 在 tickElapsed 中，chaosValue ∈ [31, 60] 时
if (chaos >= 31 && chaos <= 60 && Math.random() < 0.015) {  // 每帧 1.5% 概率，约 20s 一次
  const doors = ['cnt-front-door', 'cnt-bedroom-door', 'cnt-dining-door']
  const target = doors[Math.floor(Math.random() * doors.length)]
  // 视觉：门晃动动画
  // 交互：若门当前 open，30% 概率关闭
  get().triggerEventEffect('wind-door')
}
```

#### 4.3.2 电器断电（61~80）

```typescript
// chaosValue ∈ [61, 80] 时
if (chaos >= 61 && chaos <= 80 && Math.random() < 0.02) {  // 每 15s 一次
  const appliances = ['cnt-dining-fridge', 'cnt-living-tv', 'cnt-dining-microwave']
  const target = appliances[Math.floor(Math.random() * appliances.length)]
  // 容器临时 disabled 10s
  set({ containerStates: { ...get().containerStates, [target]: { ...get().containerStates[target], disabled: true } } })
  setTimeout(() => { /* 恢复 */ }, 10000)
  get().addEventToast(`⚡ ${target} 断电了！10 秒后恢复`, 'event', 4000)
}
```

#### 4.3.3 物品移位（81~100）

```typescript
// chaosValue ∈ [81, 100] 时，每 15s 必触发
if (chaos >= 81 && lastMoveTime + 15000 < Date.now()) {
  const movableItems = get().entities.filter(e =>
    e.status === 'placed' && !achievedGoalIds.has(`g-${e.configId}`)
  )
  if (movableItems.length > 0) {
    const target = movableItems[Math.floor(Math.random() * movableItems.length)]
    const rooms = ['living', 'bedroom', 'dining', 'entrance']
    const newRoom = rooms[Math.floor(Math.random() * rooms.length)]
    get().applyScriptedMove(target.configId, newRoom, { x: randX, y: 0, z: randZ })
    get().markMemoryOutdated(target.configId)
  }
}
```

### 4.4 各关混沌值范围

| 关卡 | 起始 | 峰值 | 是否影响玩法 |
|------|------|------|-------------|
| L1 | 0 | 0 | 否（纯教程） |
| L2 | 0 | ~20 | 否（仅展示） |
| L3 | 0 | ~40 | 否（仅记忆衰减 ×1.5） |
| L4 | 0 | ~60 | 边缘（接近 glitch 阈值，轻微视觉） |
| L5 | 50 | ~95 | **是**（全面生效） |
