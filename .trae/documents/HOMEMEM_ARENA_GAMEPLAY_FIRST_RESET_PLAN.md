## 1. 当前游戏为何不好玩（FACT，来自 G-1 三关真实截图 + 玩家视角体验）

### 1.1 L1（clean-table · 初次整理）不好玩的根因
| 证据 | 问题 |
|---|---|
| 截图 #L1-02 | **记忆系统纯形式化（0 挑战）**：3 件物品（脏杯子 / 餐巾纸 / 叉子）就摆在玩家眼前的餐桌上，"先按 E 保存位置记忆"完全是走过场——物品从未离开玩家视线，根本不需要"记忆"。 |
| 截图 #L1-01 | **物品无标签 × 机械重复**：6 只灰色容器 / 餐具排成一条直线摆在紫色"棺材状"餐桌上，玩家无法一眼区分哪只是脏杯子、哪个是餐巾纸、哪个是餐具架的目标。 |

### 1.3 L3（laundry-sort · 洗衣幽灵）不好玩的根因
| 证据 | 问题 |
|---|---|
| 截图 #L3-01 | **开场 10 秒全被对话框挡住**：玩家进入 L3 的第一眼不是 3D 场景，而是「袜子幽灵」卡通头像 + 长文字 + 两个按钮的 Modal。L3 的剧情文案对玩法本身没有增量信息，纯拖时间。 |
| 截图 #L3-02 | **全灰色场景 + 衣服与地面同色**：进入游戏后 Laundry 房间是暗褐色调，所有衣物（白/深/毛巾）散落在暗褐色地砖上几乎融为一体。玩家"找白色衣服"要凑近一件件看，眼睛非常累。 |
| 截图 #L3-02 HUD + 浮字 | **第一步引导矛盾**：当前目标写「按 E 记录**白色衣物**位置，准备分类」，但玩家出生脚边的第一条浮字是 **「F 拾取 黑袜子」/「E 保存 黑袜子 的位置记忆」**。玩家按 E 保存了"黑袜子"（非白色）→ HUD 进度条依然 0/4 → 困惑：我保存错了？还是系统不算数？ |
| 实玩漏斗 L3-10 | **9 件衣物 = 36 次机械动作**：每件衣服都要"走近 → E 保存 → F 拾取 → 走到篮子 → F 放置"，一共 9 × 5 = 45 次按键，没有任何扰动。10 分钟游戏里 8 分钟是重复劳动。 |

### 1.4 三关共性「不好玩」4 条
1. **记忆决策密度 < 0.1 次/分钟**：平均 10 分钟才产生一次"需要用到记忆"的决策，其余都是走路和机械按键。
2. **视觉 × 碰撞 × 交互三位一体错位**：同一语义家具出现 2 个视觉 mesh、1 个碰撞体、1 个真实交互 TC（8 类双重真值源 DTS），玩家用眼睛判断的"交互点"80% 是错的。
3. **HUD 信息过载**：首次玩家需要同时处理 10+ 层 UI，但真正关键的"目标、下一步、E/F 用法"只占 20% 的视觉面积。
4. **反馈缺失 / 反馈过晚**：记忆过期时记忆槽只是颜色变暗（玩家从未被教过），错放衣物只是 toast 弹一句"放错了"没任何视觉反馈，猫事件前玩家没有任何"猫在客厅"的暗示。

## 2. 当前游戏为何难理解（FACT + INFERENCE）

### 2.1 开发者自己也"进入游戏后不能立刻理解怎么玩"——5 层证据
| 层级 | 事实证据（FACT） | 影响（INFERENCE） |
|---|---|---|
| **L0 文字层**：玩法依赖"操作提示 listitem" | 简报里只有 3 条 listitem（WASD / V-E-F / 抽屉提示），**没有图示、没有高亮、没有分阶引导**。E 与 F 的区别是什么？保存记忆后有什么用？全部靠文字猜。 | 新玩家前 20 秒在"我到底该先按 E 还是先按 F"之间徘徊。 |
| **L1 视觉层**：目标物品与干扰物品无视觉差异 | L1 脏杯子 / 餐巾纸 / 叉子 vs 干净杯子 / 碗 都是灰色 primitive，没有白边高亮、没有外框、没有形状区分；L3 白衬衫 / 深色裤子 / 毛巾 颜色在暗灰场景下几乎一样。 | 玩家即使理解了 E/F 也不知道"对哪个物体用"。 |
| **L2 空间层**：关键物品藏在"视觉不对位"的家具里 | L2 手机藏在「右床头柜抽屉」——但 TC cnt-nightstand 坐标与 Room3D 右床头柜 visual 错位 1.8m，玩家按 visual 床头柜按 F 按 5 次没反应，10 次里 8 次以为是 Bug。 | 玩家误以为自己"操作不对"，实际是"空间误导"。 |
| **L3 系统层**：评分 / 评级 / 混乱值 / 小地图 / 记忆锁定 6 个系统同时出现 | L1 教学关 HUD 有 6 个系统指标，但 90% 玩家 L1 通关时都不知道"混乱值 20%"的含义、不知道"评级 D"是扣分了还是加分了、不知道记忆锁定按钮怎么用。 | 首次体验认知负担 > 工作记忆容量（Miller 7±2 定律直接超限）。 |
| **L4 叙事层**：扰动前 0 铺垫 | L2 猫事件是"猫突然把钥匙推走"——事件前 0 次提到客厅有猫、0 次出现"猫脚印"视觉伏笔、0 声猫叫音效。玩家看到事件只会想"这是什么东西？和我有什么关系？"，而不会自然想到"啊！我之前按 E 保存的钥匙记忆过期了！"。 | 核心认知闭环「保存 → 过期 → 重新搜索 → 更新」**完全无法被玩家自然理解**。 |

### 2.2 开发者为什么也不知道怎么玩？
**FACT**：从 `src/data/tasks/clean-table.ts` / `leave-home.ts` / `laundry-sort.ts` 源码可见，每关的阶段机、扰动触发、目标 predicate 全是"代码里写清楚了"但 UI 里**只字未提**的隐式规则。
- 例子 1：L2 的「钥匙必须先放回茶几再离房 → 猫才会推」只有代码里的 predicate 有，UI 没有任何文字 / 浮字 / 图示；
- 例子 2：L3 的「神秘彩色衬衫要入白色衣物篮」只在简报 briefing 里一句带过，玩家进入 L3 第一眼已经被袜子幽灵对话框覆盖了 briefing；
- 例子 3：玩家 HUD 上「记忆槽变灰」是什么意思？代码中对应 memory.outdated=true，但 HUD 没有 tooltip、说明文档、记忆系统帮助对话框（记忆系统帮助按钮点开是 2 段文字，80% 玩家不会点）。

**INFERENCE**：开发者之所以「自己进入游戏后也不能立刻理解怎么玩」，是因为当前实现是**"代码闭环完整、玩家闭环断裂"**的状态——所有规则都被写进代码 predicate 里了，但没有被"翻译"成普通玩家能理解的视觉 / 听觉 / 动效语言。

| 7 | 哪些模型会被误认成任务目标 | 3 个洗衣篮颜色与地板差异不明显（尤其深色篮在暗光里几乎看不见）；衣物本身是小 mesh，远距离全像小石子，无法用形状区分衬衫 / 裤子 / 毛巾 |
| 8 | 哪些家具布局不自然 | 洗衣间没有洗衣机！只有 3 个篮子和一堆衣服，这根本不像真实洗衣间；3 个篮子沿一面墙等距排列（像货架不像家居场景） |
| 9 | 哪些路线太长 | 9 件衣物散布在整个房间，玩家要走完整张房间对角线两次（收集所有衣服），加上 3 个篮子位置几乎在同一条线（折返效率低），总动线 ≈ 30m 是三关最长 |
| 10 | 哪些操作只是机械重复 | **9 × 5 = 45 次按键**：每件衣服「走近 → E → F → 走篮 → F」×9；而且分错类别不会有真正惩罚（toast 一句"放错了"，衣服还在手里），策略压力为 0 |
| 11 | 哪些时刻真正产生了有意义的决策 | **0~1 次**：只有遇到神秘彩色衬衫时玩家犹豫一下"放白还是放深"；其余 8 件颜色区分太简单（白=浅色、深=深色、毛巾=有毛圈纹理），不需要任何记忆 |
| 12 | 是否能够不看源码完成关卡 | 80%+，但玩家会在 2 分钟后觉得"眼睛累 + 手指酸"，完成后评价是"这关跟记忆没什么关系，就是分类衣服的体力活" |

## 4. 玩家体验漏斗（12 步 × 3 关，每步保留/删除/重做建议）

### 4.1 L1 漏斗（clean-table）——核心断裂点：保存记忆「无必要」
```
进入关卡 (100%)
  → 理解目标    85%（目标面板文字基本清楚，但"为什么要先保存"不懂）
  → 理解操作    70%（E vs F 30% 玩家顺序弄反，15% 被 toast 打回）
  → 找到目标    55%（6 个灰色餐具无标签，45% 玩家先对非目标物品 F）
  → 第一次正确动作  40%（25% 死在"先 F 后 E 被打回 → 回退 E 保存又找不到同一物体"）
  → 第一次阶段推进  35%（保存完第一个物品，阶段还是 1/3，玩家不知道"还需要 E 剩下两件"）
  → 遇到扰动      0%（L1 没有扰动！BREAKER #1）
  → 理解扰动      N/A（没扰动，直接跳）
  → 恢复任务      30%（机械放完第 2、3 件，但此时已经忘了"记忆系统存在"）
  → 完成         25%
  → Probe        15%（Probe 题目 3 问，玩家答不出"我刚才保存了哪件的位置"→ 全靠猜）
  → Result       10%（看完评分/评级/混乱值一堆数字，不知道自己好在哪坏在哪）
```

**漏斗结论**：L1 完成率估计 **10~25%**，最大断裂点出现在「遇到扰动 0%」——玩家根本没体会到"记忆系统的必要性"，就直接通关（或失败退出）。

**每步建议**：
| 步骤 | 玩家看见什么 | 要理解什么 | 当前反馈 | 失败原因 | 多余/重复 | 误导 | 建议 |
|---|---|---|---|---|---|---|---|
| 理解目标 | 目标面板 3 行 + 3 个空圈 | "我要把桌上 3 件东西放对地方，先按 E 记住位置，之后东西会被移动" | 只有文字，无图示 | 没说"东西会被动"→ 记忆无意义 | 顶部评分/评级/混乱值 3 项干扰 | — | **重做**：目标面板第一步只写「第 1 步：记住桌上 3 件东西」+ 餐桌 3 件物品白边高亮；**删除**：L1 HUD 评分/评级/混乱值 |
| 理解操作 | listitem "E 保存 F 交互" | E=拍照存档，F=伸手拿/放 | 没有区分图示 | 顺序反了被打回 | 底部操作提示 7 条信息挤在一起 | — | **重做**：L1 分 3 步教学气泡依次出现：① 靠近物体时 E→记忆槽点亮一张图；② 接着按 F→拿起物体；③ 走到容器旁 F→放置。其他提示**隐藏** |
| 遇到扰动 | — | 保存完记忆后，3 件物品被移动到桌下/其他位置再回到原位 1 件 —— 玩家发现位置变化 | 0（当前没扰动） | BREAKER #1 | — | — | **新增**（最小扰动）：保存完记忆 5 秒后脏杯子在桌上被小幅度移动 30cm + 出现"小浣熊搬东西跑了"的小脚印 1 条；**保留**：幅度不要大，只验证"玩家会用 E 的记录回看位置" |
| Probe | — | "刚才保存的脏杯子原来在哪个位置？" | 3 题文字问卷 | 玩家没理解记忆意义 → 猜 | — | — | **简化**：Probe 只用 1 题（L1 教学级）+ 用俯视图小方块点击不用文字；**保留**：不要因为 Probe 简单就删掉（它是行为研究数据的锚点） |

### 4.2 L2 漏斗（leave-home）——核心断裂点：**猫事件被玩家开局跳过**
```
进入关卡 (100%)
  → 理解目标    90%（文字懂，但手机/雨伞在哪不知道）
  → 理解操作    85%（E/F 有 L1 基础）
  → 找到钥匙    99%（出生就在钥匙脚边）
  → 第一次正确动作（先 E 再 F）  <10%（BREAKER #1：90% 玩家先 F 拿钥匙 → 钥匙 status!='free' → 猫事件永远不触发）
  → 第一次阶段推进  70%（拿了钥匙/保存了钥匙，阶段 1/3）
  → 遇到扰动     <5%（只有不到 5% 玩家走了"先 E 不拿钥匙就去卧室/玄关 → 再回来"路径）
  → 理解扰动     <3%（扰动都没发生，无法理解"旧记忆失效"）
  → 恢复任务     40%（拿到手机、雨伞后，钥匙在手里直接放玄关托盘，没发生找钥匙的环节）
  → 完成         35%
  → Probe        15%（没经历找钥匙，Probe 的"钥匙旧位置 vs 新位置"题全靠猜）
  → Result       10%
```

**漏斗结论**：L2 「长程记忆 + 扰动恢复」闭环**在 90%+ session 里从未发生**，原因是玩家第一眼就看到"F 拾取 钥匙"大浮字，直接拿走钥匙。自然路径的核心高光被跳过。

**每步建议**：
| 步骤 | 当前状态 | 失败原因 | 误导 | 建议 |
|---|---|---|---|---|
| 第一次正确动作（先 E 钥匙） | <10% 通过 | "F 拾取 钥匙"浮字比"E 保存"更显眼，玩家直觉先 F 拿 | F 浮字在出生 0.5s 就出现，抢占 E 的引导 | **重做**：钥匙出现在茶几上 2m 远 + 茶几正对着玩家出生视线（旋转玩家 spawnRotation -π/2，面朝茶几不是卧室门）+ **前 3 秒只弹 E 保存浮字（锁死 F 拾取）**，等玩家按完 E 后才允许 F。这是 L2 的第一优先级修复。 |
| 离开客厅的引导 | 无线索 | HUD 目标只说"找到手机"不说手机在哪 | 小地图上 bedroom/entrance 图标没有"关键目标在此"的高亮 | **保留**：不要改成文字写"手机在卧室"；**新增**：小地图上 bedroom 房有闪烁图标（手机）+ entrance 有闪烁图标（雨伞），视觉引导不破坏探索感 |
| 遇到扰动（cat push key） | 5% session 触发 | 条件：keyFreshSaved + keyFree + leftLiving。玩家先 F 拿了 → keyFree 永远不满足；又没离开客厅 → leftLiving 不满足 | 开局钥匙在玩家脚边 → 玩家不会不拿钥匙就走 | **重做**：① 钥匙移到茶几正中央（玩家需要走 2m 才到），茶几正对着出生视线；② 保存完 E 后 HUD 目标立刻变成"先去拿手机"（引导玩家离开客厅），并在门口放蓝色箭头。**强制玩家先离开 Living 而不是先 F 拿钥匙**，确保猫事件 90%+ session 触发。 |
| 恢复任务（找新位置） | 3% 经历过 | 猫事件没触发所以没恢复 | 钥匙新位置若放在家具缝隙/墙角，玩家搜不到 | **重做**：钥匙移动后要放在"猫脚印 3 步 → 钥匙"的可视路径上，脚印是白色发光 3 秒，玩家顺着脚印就能发现。**绝对不能把钥匙瞬移到看不见的角落**。 |

| 8 | L2 旧记忆失效是否被玩家理解 | **INFERENCE：** 在 <5% session 里被理解。根本原因是"过期记忆"的视觉反馈太弱：记忆槽里只是颜色变暗（从未被教学过），没有任何红框闪烁、没有"过期"字样、猫推钥匙前没有铺垫。即使真触发了，玩家也只会觉得"哦，东西位置变了"，而不会联想到"啊！我之前 E 保存的那条记忆过期了——我要更新！" | INFERENCE |
| 9 | L3 是否真的超过了玩家记忆容量 | **INFERENCE：** 完全没有。L3 容量应该是 Miller 7±2 的级别，但当前 L3 只需要记住"白/深/毛巾"3 类（视觉区分，不用位置），远低于工作记忆容量。L3 的问题反而是：**任务太简单、完全不需要位置记忆。** | INFERENCE |
| 10 | 哪些系统可以暂时隐藏或删除 | **RECOMMENDATION：见 §10 系统删减矩阵。** 结论是：L1 教学关隐藏 6 个系统（评分/评级/混乱值/小地图放大缩小全屏地图/记忆锁定按钮），L2 再逐步解锁；多层 Toast 合并；Dialog 开场全删；研究术语（比如"Spatial Validity Certification"）全部隐藏在 QA 附件里，玩家 UI 不出现。 | RECOMMENDATION |

**一句话核心乐趣定义（RECOMMENDATION，作为本计划的总锚点）：**
> **"在家这个最熟悉的空间里，玩家用『拍照式记忆（E）』存档物品位置 → 离开房间 → 环境悄悄被猫/幽灵/浣熊扰动 → 玩家回来发现现实与记忆不符 → 顺着痕迹重新搜索 → 更新记忆 → 完成任务。Aha Moment = 『我记得的位置是错的！我被骗了！』的瞬间。"**

> 如果一个玩家玩完了 L2 却从未经历过「我被骗了」的惊讶，那他/她其实没玩过 HomeMem Arena——只是玩了一款「搬运模拟器」。本计划所有工作包都围绕"如何把这个 Aha Moment 的触发率从 <5% 提升到 ≥ 80%"。

## 6. L1 重设计

### 6.1 L1 重设计锚点（最小循环）
```
看见物品（餐桌上 3 件唯一视觉区分的物品）
 → E 保存（记忆槽里出现对应物品的缩略图）
 → 记忆卡变化（从 空→点亮，3 秒后出现"浣熊脚印"：有东西来过了的暗示）

 → 看见明显目标容器（3 个容器在同一直线上、用颜色+文字区分）

```

### 6.2 L1 具体改动清单（只写允许改的域）

## 7. L2 旗舰关重设计

### 7.1 L2 重设计核心高光（固定不变，所有工作包向它对齐）
```
【玩家出生视线】：正对沙发+茶几（不是正对卧室门！），茶几中央有一把发光的钥匙
```

## 8. 房间布局原则（作为 WP-R 到 WP-2.1/2.2/2.3 的硬约束）

> 这些原则来源于「三关实玩中玩家抱怨的家具布局不自然」+ 真实住宅常识 + QA 自动化可达性检查的交集。

### 8.1 7 条不可违反的布局原则（HARD CONSTRAINT）
| # | 原则 | 反例（当前实现里的问题） | 自动 QA 检查方式 |
|---|---|---|---|
| H1 | **语义家具 visual × collision × TC 必须 1:1:1** | 玄关 tray ×2 visual / umbrella ×2 visual → 2 个视觉 1 个 TC → 玩家按视觉 F 按不到 | QA G1：semanticKey 在 DF 和 TC 中唯一，同一 semanticKey 只能有 ≤1 条 visual（Room3D）+ ≤1 条 TC + ≤1 条 DF collision |
| H2 | **主通道净宽 ≥ 1.2m**；交互点（TC 附近）净空 ≥ 0.8m × 0.8m | L2 Bedroom chair 压 bedroom 门洞 → 玩家要斜着走；Living 沙发茶几之间 < 0.8m | QA G4：门洞与 DF/TC AABB 不重叠；QA R1：TC 周围 0.8m×0.8m 区域内无 DF collision |
| H3 | **玩家出生视线必须正对当前阶段的最关键目标** | L2 出生正对卧室门（关键目标是钥匙在茶几） | 阶段 0 时，playerSpawn 朝向向量与关键目标位置夹角 ≤ 30°（蓝图约束，未来 QA R4 新 Gate） |
| H4 | **房间尺寸与家具尺寸要真实住宅量级（×0.8~1.2 公差）** | Living 沙发 2.4m 长（正常），但房间只有 5m 宽 → 放完沙发通道窄；L1 餐桌 3.5m 长 + 4 个餐具一字排开 → 不像真实餐桌 | 家具尺寸与真实家具尺寸比值 ≤ 1.3 ≥ 0.7（QA S3 新 Gate） |
| H5 | **门的位置必须与真实房间动线一致**：L2 户型三房的门——Living→Bedroom 在西侧、Living→Entrance 在东侧、Living→Kitchen 在南侧，门不能被电视柜挡 | Living 电视柜位置挡了一半南侧门洞 | QA G4：DF/TC AABB 不压任意门的门洞矩形（门的位置从 `sharedRooms[roomId].doorways`） |
| H6 | **扰动后新物体位置必须在玩家主视线 30° 内，且有痕迹可达** | 猫把钥匙推到家具缝隙 / 墙角 | QA R2：新位置相对玩家从门洞进的主视角夹角 ≤ 30°，新旧位置连线 0.5m 步长每步无碰撞（痕迹可达） |
| H7 | **目标容器 / 目标物品必须有「非语言视觉提示」**（颜色外框 / 发光 / 浮字图标），不能只靠文字让玩家猜 | L1 洗碗机 / 垃圾桶 / 餐具架 用文字区分，玩家 45% 把非目标物品当成目标 | QA V1（视觉 QA，人工）：首次进入 3 秒内能说出 ≥ 2/3 目标容器的用途 |

## 9. 美术方向（2~3 种 Web 项目统一美术方案）

### 9.1 三种方向对比
| 维度 | **方向 A：Stylized Low-Poly Warm Home（推荐）** | 方向 B：Cozy Miniature Diorama | 方向 C：Clean Cartoon Household Robot |
|---|---|---|---|
| 与玩法匹配度 | ⭐⭐⭐⭐⭐ 低多边形的"抽象 + 暖色调"不会分散对目标物品的注意力；柔软边缘与"猫/浣熊的家"主题契合 | ⭐⭐⭐⭐ 玩具屋风格让"家"更有封闭感，但是俯视强（对第一人称 FPS 视角不友好） | ⭐⭐⭐ 机器人家政主题可以加"AI 拍照记忆 E"的世界观，但与当前"猫/幽灵/浣熊"叙事错位 |

### 11.2 为什么本路线与上一版「治理优先」路线顺序不同？（解释调整原因）
> 上一版顺序是 P0-STABILITY → P2.G1 基础设施 3 个工作包 → P2.0-R 蓝图 → P2.1 Living → P2.2 → P2.3 → P2.4 → P3 美术 → P4 时间线 → P5 试玩。
>
> **本 Gameplay-First 版调整的原因 4 条（FACT 级依据）：**
> 1. **L1 教学断裂是最紧急的用户断点**：三关漏斗最高的流失发生在 L1（完成率 10~25%），而不是 L2。L1 都过不了，L2 的"猫 Aha Moment"玩家根本不会看到。所以把「L1 教学简化」放到 G1 最前面，让玩家至少能玩通一关再说。
> 2. **G2 最小场景治理是 L2 视觉重做的硬前置，但不需要拆成 3 个独立 WP**：collision/QA/surface 这三项统一在一个 G2 Gate 内做完即可（本质都是为了让 G3~G5 改家具坐标时碰撞和 QA 能跟上），没必要拆成 3 个 commit 分开 push。基础设施类 Gate 一起合并走更高效。
> 3. **把 P2.0-R「蓝图 APPROVED」拆进 G3~G5 每房内部**：上一版要先把三房蓝图全部 APPROVED 再实施，但本路线要先改 L1（G1），L1 改完玩家反馈可能反过来影响 L2 布局决策。所以不再做"集中先批蓝图"，而是每房"边量边做边 QA 盖章"（每房独立 ASCII 俯视图 + QA Gate 签字），更贴合本版"可见效果优先"的原则。
> 4. **L3 从"第 3 关重点"降级为"冻结可玩"**：上一版 P2.4 单独做 Laundry/Dining 兼容。但本版实玩证明 L3 设计本身不需要位置记忆（是颜色分类体力活）——短期不再投入。G7 统一美术时顺手给 L3 换浅地砖+衣服颜色区分即可，不再单独做 Laundry 布局治理。

## 最终 6 个必答问题总结（本计划核心结论，对照 §十用户要求）

### Q1. 现在为什么不好玩？
**答（FACT+INFERENCE）：** 3 层根本原因叠加：
1. **记忆决策密度 < 0.1 次/分钟**：10 分钟才产生一次"需要回忆"的思考，其余 99% 是 WASD 走路 + E→F→放机械按键；
2. **Aha Moment 触发率 <5%（核心产品灵魂几乎从未发生）**：L2 猫事件被玩家开局 F 拿钥匙跳过，L1 没有扰动、L3 不需要位置记忆；
3. **97% 失败来自 UX / Bug / 视觉错位而非记忆策略**：Duplicate Visual（托盘×2/伞架×2/茶几×2）+ OT 床头柜错位 1.8m + L3 全灰场景颜色分不清 —— 玩家以为自己"不会玩"，实际是 8 类双重真值源（DTS）+ 引导缺失 + HUD 过载让他们不可能会玩。

### Q2. 为什么开发者自己进入游戏后也不知道怎么玩？
**答（FACT）：** 所有玩法规则（cat 触发条件 / 手机在右床头柜抽屉 / 神秘衬衫要放白篮 / 记忆过期的视觉含义）**只在代码 predicate 和 tasks/*.ts 的注释里写了**，玩家侧 UI 没有对应的图示、高亮、动画、阶段引导。就像一本数学题：答案在教师手册里，但考卷上只印了"求 x"——即使是写题目的老师，不翻教师手册也做不出这张卷。

### Q3. 哪些系统应该删减？
**答（RECOMMENDATION，对应 §10 矩阵）：** 分 4 类：
- **立刻从 L1 删除的 6 项**：评分 / 评级 / 混乱值 / 小地图 5 按钮 / 正计时 / 记忆锁定按钮；
- **全线隐藏（默认不显）4 项**：Combo / Session JSON 下载 / 事件日志 R 键面板 / 研究术语（Spatial Validity / MVP Contract） / 记忆类型中文标签；
- **必须简化的 3 项**：多层 Toast → 单例栈 1 条；Dialog 开场 Modal → 常驻左上 2 行目标面板 + 小图；Probe 文字 3 问卷 → L1 1 题、L2 2 题俯视图点击；
- **保持 KEEP 的 3 项**：E/F 机制（核心灵魂）/ 记忆槽缩略图 / Result 页总得分与分项图。

### Q4. 哪一关应该成为旗舰关？
**答（RECOMMENDATION + FACT 依据）：L2 leave-home 是旗舰关，L1 是教学关，L3 暂时冻结不优先扩展。**
- FACT 依据 1：L2 拥有 HomeMem Arena 唯一的 Aha Moment（保存记忆 → 过期 → 重新搜索 → 更新），L1 目前无扰动、L3 不需要位置记忆。只有 L2 能承载"比赛演示 3 分钟录屏"的高光时刻。
- FACT 依据 2：实玩漏斗显示 L2 修复后（保存完钥匙必须先离房 → 猫 100% 推 → 4/5 玩家 Aha），时长正好 8~12 分钟，完美落在比赛作品"单关体验 10 分钟级"的最佳时长区间。
- FACT 依据 3：本计划 G3~G6 四阶段全围绕 L2 展开（Living/Bedroom/Entrance 三房重做 + 猫演出），投入占比 50% 以上，资源集中在旗舰关是对的。

### Q5. 下一个工作包应该修改什么？
**答（RECOMMENDATION）：** G0 · 运行稳定和关卡可进入。
- 修改文件域：**tests/e2e/ 或 tests/ vitest**（新增 1 条 canvas-height-can-play 断言 spec），最多 ArenaPage 加 ≤3 行 data-testid 属性；
- 严禁修改：src/game / store / tasks 数据 / decorFurniture / 任何 3D 逻辑；
- 具体内容：5 条公开 URL 断言 canvas 高度 > 0.6vp + phase ≤5s + console 0 error 级。
- 为什么是这个：稳定 > UX > 布局 > 闭环 > 美术，G0 是所有后续 Gate 的地基。没有 G0 的断言，今天修完的 canvas 明天一个 PR 就塌了，G1~G9 所有工作随时可能在比赛现场因为 canvas 又塌了翻车。

### Q6. 为什么暂时不应该增加新关卡？
**答（RECOMMENDATION + FACT 禁令 双重依据）：**
1. **用户本轮 §三 明确禁止**：优先级约束第 1 条「新增公开关卡 / 激活 Scene Graph / 程序化房型 / 大规模剧情重写 / 正式研究众包 / 全量高模替换 / 移动端重构 / 云端账号」8 项禁令级不得进入近期 G0~G9；
2. **FACT：当前 3 关公开的漏斗完成率仅 L1=10~25% / L2=10~35% / L3=5~15%**——3 关都没做好，加第 4 关只会把 8 类双重真值源 × 6 房扩成 × 8 房、把 UX 过载问题放大 33%，不会提升比赛评分。比赛打分的核心是"产品完成度 × 技术实现 × 实用性 × 创新性"，创新分需要的是"≥ 3/5 玩家真实经历了过期记忆的 Aha Moment"，而不是"关卡数量多"；
3. **INFERENCE：在资源有限时，做深 L1（教学简化）+ 做透 L2（旗舰 Aha），比做宽 4 关好 10 倍。** 本计划退出标准 §13.10 只要求 3 名陌生玩家玩 L1 + L2，根本不需要第 4 关来证明产品成立。加新关卡应该推迟到 G9 通过、MVP 研究契约 7/9 满足、比赛提交完成之后再考虑。
